🏆 OWASP CI/CD InfoSec Risks / part 2

Fireworks,

Let's look further at the risks of CI/CD,

Here we looked at an example and I gave a description for the first 5 in the carousel.

Remaining risks include hygiene of secrets before logging.

There are descriptions in the carousel, and below we will analyze several blocks with a real case from the battle

SEC-7 Insecure System Configuration

• Unpatched CVEs - Self-hosted runners and build servers with known holes

• Default credentials and open admin panels - the CI control panel sticks out onto the Internet without MFA

• Redundant network - the runner sees the entire internal circuit, and not just what the assembly needs

Case

January 2024, Jenkins CVE-2024-23897: a bug in the CLI (args4j expanded @file) allowed arbitrary files to be read on the controller - including keys and credentials.xml - escalating to RCE

Reko

• CIS Benchmark for SCM/CI/registry, disable anonymous access

• Do not expose CI admins to the Internet - only through VPN/bastion + MFA

• Runners in an isolated segment, minimum network access

SEC-9 Improper Artifact Integrity Validation

• Unsigned commits and artifacts

• Downloading without checking - installers and tools are pulled into the pipeline without checking checksum

• Deploy by tag - :latest instead of digest

• There is no SBOM and provenance, that is, it is not visible from what and how the artifact is assembled

Case

December 2020, SolarWinds (SUNBURST): attackers infiltrated the Orion build process itself and planted a backdoor in the build. The malware was included in an officially signed update and distributed to approximately 18k clients, including US government agencies. The code in the repository was clean - build was compromised, and no one checked the artifact with the source

Reko

• Signing commits and artifacts (Sigstore/ cosign), checking before deployment

• Checksum verification of all tools downloaded into the pipeline

• Deploy the image strictly by digest (@sha256:...), not by tag

• SBOM (CycloneDX) and provenance (SLSA)

• Isolation and control of the integrity of the build environment

How does it work?

# keyless cosign

cosign sign $IMG@sha256:<digest>

cosign verify --certificate-identity=... $IMG@sha256:<digest>

# Deploy strictly according to digest (on cube), not according to :latest

kubectl set image deploy/app app=$IMG@sha256:<digest>
