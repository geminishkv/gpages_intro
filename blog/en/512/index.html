🛠 OSV-Scanner - SCA from Google

Salute, let’s get back into the flow and today I’ll introduce you to a relatively new instrument.

OSV-Scanner works with OSV.dev - an aggregated database with 30+ sources: GitHub Advisory, NVD, PyPI Advisory, RustSec, Go Vuln DB, Maven Central and others, that is, through a distributed data store

Essentially, a vulnerability affecting multiple package managers is tracked as one ID - without duplication, without CVSS discrepancies between sources. Full support: npm and Maven

Has scanning of container images and guided remediation, has transitive scanning of Python via deps.dev API. Now requirements.txt shows the entire graph including indirect dependencies. Apache 2.0 License

Supports: Go, Python, JavaScript, Java, Rust, PHP, Ruby, Dart, Elixir, R, C/C++, also lockfile formats: go.mod, package-lock.json, yarn.lock, pom.xml, Cargo.lock, Gemfile.lock, composer.lock, uv.lock and others

Installation

# Go install

go install github.com/google/osv-scanner/v2/cmd/osv-scanner@latest

# Docker

docker pull ghcr.io/google/osv-scanner:latest

Teams

# Recursive directory scan

osv-scanner scan --dir .

# Specific lockfile

osv-scanner scan --lockfile ./package-lock.json

# Scanning a container image

osv-scanner scan --image myapp:latest

# JSON output for parsing in CI

osv-scanner scan --dir . --format json > osv-report.json

# HTML interactive report

osv-scanner scan --dir . --format html > report.html

Guided Remediation feature

# Minimum set of upgrades in terms of severity, depth of dependence and ROI

osv-scanner fix --dir . --strategy relock

# In-place: automatically updates lockfile

osv-scanner fix --dir . --strategy in-place

Ignoring

# osv-scanner.toml

[[IgnoredVulns]]

id = "GO-2022-0968"

ignoreUntil = "2026-12-01"

reason = "Vulnerability in a module that is not used in production"

CI/CD

# GitHubActions

- name: OSV-Scanner

uses: google/osv-scanner-action@v2

with:

scan-args: |-

--recursive

--dir=.

--format=json

--severity=HIGH,CRITICAL

# GitLab CI

osv-scanner:

image: ghcr.io/google/osv-scanner:latest

stage: security

script:

- osv-scanner scan --dir . --format json

--severity CRITICAL,HIGH > osv-report.json

artifacts:

paths: [osv-report.json]

allow_failure: false

Call Analysis

# Checks whether the vulnerable function is called in real code

# Reduces noise: there is a vulnerability, but there is no call code

osv-scanner scan --dir . --experimental-call-analysis

Total

- One vulnerability is one ID without duplicates

- Guided remediation: a minimum set of upgrades ranked by ROI

- Layer-aware scanning of containers: you can see which layer brought the vulnerable package

- Call analysis: there is a vulnerability, the function is not called - it does not make noise
