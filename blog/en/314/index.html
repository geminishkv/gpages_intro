🛠 Secure HTTP headers

So, let's look at the basics that you need to know and understand, namely security headers. Remember that these are instructions to the browser on how to handle the site's content. They are configured on the server or in the framework config and cover entire classes of attacks: XSS, clickjacking, MITM, data leakage. Without them, even a clean and tidy frontend remains vulnerable to basic exploits.

Key headings and what they do:

• Content-Security-Policy (CSP) - tells the browser where scripts, styles, images, frames can be loaded from. Trims inline-JS and third-party resources that you do not control

• Strict-Transport-Security (HSTS) - prevents the browser from accessing the site via HTTP, only HTTPS. After the first visit, the browser itself redirects to HTTPS, even if the user typed http

• X-Frame-Options - prohibits embedding a page into an <iframe> from foreign domains. Clickjacking protection. Outdated, but still needed for browsers that are supported on also outdated devices. Used in conjunction with CSP frame-ancestors

• X-Content-Type-Options - prevents the browser from guessing the MIME type of the file on its own, since without this header the browser can execute the .jpg as JavaScript

• Referrer-Policy - controls how much information about the current URL is left in the Referer header during a transition. Important for pages with tokens in the URL or sensitive paths

• Permissions-Policy - allows or denies access to the browser API (camera, microphone, geolocation, fullscreen, etc.) for the page itself and for the iframe

/etc/nginx/conf.d/security-headers.conf

server {

add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

add_header X-Frame-Options "DENY" always;

add_header X-Content-Type-Options "nosniff" always;

add_header Referrer-Policy "strict-origin-when-cross-origin" always;

add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

# CSP - starting strict policy

add_header Content-Security-Policy "

default-src 'self';

script-src 'self';

style-src 'self' 'unsafe-inline';

img-src 'self' https:;

font-src 'self';

connect-src 'self';

frame-ancestors 'none';

base-uri 'self';

form-action 'self';

"always;

}

Check headlines and online

# Via curl - look at the headers of the response

curl -I https://example.com

# More details - only security-relevant headers

curl -s -D - https://example.com -o /dev/null | grep -iE\

"strict-transport|content-security|x-frame|x-content-type|referrer|permissions"

Total:

• You should start with Content-Security-Policy-Report-Only - the header logs violations, but does not block yet. Look at the logs and remove errors

• frame-ancestors 'none' in CSP completely replaces X-Frame-Options: DENY

• Do not set the max-age for HSTS below one year - otherwise it will be of little use. preload adds the site to the browser preload list, after which HTTPS will be required even before the first request

• Permissions-Policy - set explicitly, even if you prohibit everything: camera=(), microphone=(), payment=()
