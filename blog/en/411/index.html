🛠 Security SBOM generator with vulnerability chechup v2.2.0

Salute,

UwU, today I want to share the Tula, which received a major improvement. I previously wrote about it here.

This tool helps you quickly and in a more convenient form collect SBOM for a project that maps vulnerabilities according to SCA, Container Security, and it will be especially useful for certification according to FSTEC of Russia, including monitoring your supply-chain.

What does it do?

• Generates SBOM with two generators (cdxgen + syft) and combines the result - from a local directory, a Git repository (GitHub / GitLab) or a container image

• Deduplicates components by PURL and vulnerabilities by CVE and component

• Creates two signed SBOMs: without vulnerabilities and with them

• Scans vulnerabilities in parallel via Trivy, OWASP Dependency-Check, Clair

• Embeds detected vulnerabilities into SBOM (CycloneDX)

• Optionally enriches vulnerabilities with BDU identifiers of the FSTEC of Russia

• Exports readable reports: Excel (.xlsx), Word (.docx), ODT (.odt)

• Prepares SBOM according to FSTEC requirements (`secsbom cert` - GOST fields)

Read about the release itself here. A lot has been fixed, enriched, and Tula has become much more convenient for you, try it, it will help you in assessing the risks and vulnerabilities of software at your work.

In any case, there are mistakes, but you can still help me with them 😅

Reko by run

$ pip install sbom-pipeline # 1. install

$ cd /path/to/project # 2. go to the ROOT of the project

$ secsbom status # 3. check environment

$ secsbom gen-sbom --path . #4. build SBOM (components only)

$ secsbom scan secgensbom_out/app-bom-dedup-signed.json --path . --bdu # 5. map vulnerabilities

$ secsbom info secgensbom_out/merged-bom-signed.json # 6. summary: components and CVEs by severity

$ secsbom verify secgensbom_out/merged-bom-signed.json # 7. verify integrity
