🛠 Clair for Docker and OCI

Salute,

Let's talk today about an open-source engine for analyzing Docker/OCI images for vulnerabilities.

The tool is written in Golang and parses the image layer by layer, that is, it extracts a list of installed packages and compares them with CVE databases without running a container. Clair can work in combined mode (combo) - all three services in one process, which is convenient for testing, or in distributed mode for scaling in production

Developed by the Quay team under the Apache 2.0 license. Report formats: CLI, SARIF, Quay-native JSON. Works with Ubuntu, Debian, RHEL, Suse, Oracle, Alpine, AWS Linux, VMWare Photon, Python and more

Functionality

• Indexing - receives the image manifest, extracts layers, scans their contents and generates an intermediate report

• Compares data from the interim report with the database of known vulnerabilities and returns real vulnerabilities

• When new detections are detected, it determines which of the previously indexed images they affect and sends notifications according to the settings

Chips

• Analyzes images statically - no need to run the container, everything is at the manifest and layer level

• Supports vulnerability databases: NVD, Alpine SecDB, RHEL, Ubuntu, Debian, Oracle and others

• Notifier mode - when a new CVE appears for an already verified image, it will send a webhook, without rescanning

• SARIF for GitHub Security, GitLab SAST Code Scanning

• JSON for DefectDojo, Jira, Quay Registry

• Scales horizontally: Indexer / Matcher / Notifier are distributed across separate instances for load

• Built into Red Hat Quay as the main engine for scanning images in the registry (Red Hat is understandable, but reused)

Teams

# Set clairctl

go install github.com/quay/clair/v4/cmd/clairctl@latest

# Scan public image

clairctl report --host http://localhost:6060 ubuntu:focal

# Scan with config (if PSK-auth is enabled)

clairctl report\

--config ./config/clair.yaml \

--host http://localhost:6060 \

nginx:1.25

# Check

docker compose up -d

curl http://localhost:6061/healthz

# API Indexer check

curl http://localhost:8080/indexer/api/v1/index_stat

# Example output:

# ubuntu:focal found libpcre3 2:8.39-12build1 CVE-2017-11164

# ubuntu:focal found libc6 2.31-0ubuntu9 CVE-2016-10228

# ubuntu:focal found libgcrypt20 1.8.5-5ubuntu1 CVE-2019-12904

Example clair.yaml config

# config/clair.yaml

http_listen_addr: ":6060"

introspection_addr: ":6061"

log_level: debug

indexer:

connstring: "host=clair-db port=5432 user=clair dbname=clair sslmode=disable"

migrations: true

matcher:

connstring: "host=clair-db port=5432 user=clair dbname=clair sslmode=disable"

migrations: true

notifier:

connstring: "host=clair-db port=5432 user=clair dbname=clair sslmode=disable"

migrations: true

webhook:

target: "https://your-service/clair-webhook"

callback: "http://clair:6060/notifier/api/v1/notifications"

CVE Caching for Optimization

# Separate workflow - updates the database once a day

name: Update Clair DB

on:

schedule:

- cron: '0 5 * * *'

jobs:

update-db:

runs-on: ubuntu-latest

steps:

- name: Generate vulnerability DB

uses: quay/clair-action@main

with:

db-file: matcher.db

mode: update

- name: Cache DB

uses: actions/cache@v3

with:

path: matcher.db

key: clair-matcher-db

Total

Clair comes in if you already have Quay or need an engine that can be built into the registry and CI at the same time, namely, it scans during push, keeps the database up-to-date and alerts for new CVEs without repeated runs.

If you want to try it in conjunction with other tools, look towards the Clair + DefectDojo + SecScore combination for a full-fledged Security Gate.
